## 二、根因链（五环，日志+源码双证）

1. **历史图片字节随每次请求全量重发**——DSH 追加式表面每轮重派生请求面，5 图持续在场（此为**最根本结构性前提**）
2. **网关侧多模态装载确定性故障**——SGLang `legacy_load_mm_data` 崩溃（错误串冒号后空白=裸 StopIteration 特征）；生产恢复本身证明：只要表面含 ≥1 活图必复发，图移除后同网关（仍故障）即成功
3. **状态盲分类→零重试**——失败在 200-OK SSE 流内，无 HTTP 状态可判；pi-ai 把错误扁平化为纯文本（`stream.ts:34` 自注 "XXX(pi-ai upstream)"），文本正则不中 → `PI_AI_ERROR`，不在 `DEFAULT_RETRYABLE_CODES`（`retry-policy.ts:18`）→ 轮即刻终止
4. **无内容降级路径**——原生 image-offload 仅由 `IMAGE_OFFLOAD_REQUIRED`（字节/像素预算超限）触发；7–16KB 小图永远够不到阈值
5. **不可变历史→确定性重放**——致毒内容无法自愈，7 个失败轮/8 次人工按键/约 21 小时

**最根本一环 = 第 1 环**：图片字节常驻请求面。它把一次网关瞬时故障（第 2 环）经 3/4/5 环放大为永久卡死；若无第 1 环，第 2 环只是一次可重试/可绕过的普通错误。

## 四、同类框架机制对照（机制层归纳）

Claude Code / Codex 类 Agent 框架在机制上不存在此故障类的放大链：**(a)** 图片附着于具体消息/工具结果而非随全史重发——历史压缩（compaction/摘要）天然淘汰旧图字节；**(b)** API 错误携带类型化状态（5xx/overloaded→客户端退避重试），无"流内文本扁平化+正则误分类"环节；**(c)** 超限工具产物有修剪机制（pruner 类），内容不永久毒化追加式历史。DSH 的差异点恰是第 1/3 环——本插件以"入会即归档"在插件层补齐了 (a) 的等效语义（官方 offload 标记为持久语义、缩略图与计价无损），而 (b) 属宿主适配器层、超出插件职责（社区 #11503/#8844 家族仍开放）。
