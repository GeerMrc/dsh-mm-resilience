# dsh-mm-resilience

DSH 桌面客户端（0.2.2-rc.3 已核验）第三方插件：**图片解析归档复用**——每张图片首次入会时解析一次并归档打标，此后所有请求零图片字节重发，从根源上消灭"多模态网关故障卡死会话"这一故障类（[故障报告](docs/fault-report-session-0e2f3132.md)）。

## 工作原理（纯预防，零补救）

```
贴图 ──pre-step──▶ 图片块标 offloaded:true（缩略图保留）
                 + 旁挂机器描述标签（含 provider/model 来源行）
                        │
所有后续请求 ◀── projectOffloadedImages：图片字节→官方占位文本
                        │
模型/用户明示回看 ──▶ mm_view_image 工具（下一个请求附原图恰好一次）
                        │
下一个 pre-step ──▶ 有日志的 surface replace 出清像素
```

- **解析一次**：贴图瞬间经**会话当前所选模型**（无独立路由——非多模态模型则解析不可用、归档不带描述，即官方正确行为）做一次单图描述调用（有界并发/单次超时/总额硬预算/attachmentId 缓存）；失败=仅归档不带描述，绝不阻塞发送。
- **终身复用**：持久化的 user/message 即档案；同图重贴同 attachmentId 直接命中缓存。
- **明示回看**：`mm_view_image(attachmentId)`（与原生 `read_image` 区别：本工具按会话内 attachmentId 查看贴图，read_image 读文件路径）；仅在视觉路由上暴露；像素随其后第一个请求传递恰好一次，再下一个请求前出清（重启后至多多搭一轮）。
- **总开关 = 插件页右上官方启停开关**：安装即自动启用并接管；关闭即整个插件（宿主半+卡片）卸载、**官方功能自动接管**（原生压缩默认/原生准入上限/新贴图不再归档；历史归档标记为官方持久语义保留）；重新开启配置不丢。注意：桌面端关闭后可能提示需重启 DSH 才完全生效（宿主无 HMR）。

## 设置卡（插件页 → dsh-mm-resilience，官方「子智能体」卡同构）

官方扁平风格：区块标题（旁 ⓘ 悬停说明）+ 官方字段（ⓘ 帮助/已覆盖徽章/恢复默认）+ 官方保存条。**默认值 = DSH 官方默认（安装即接管一致态）**：

| 设置 | 默认（=官方） | 说明 |
|---|---|---|
| 图片像素上限（宽×高总像素） | 2048×2048=4,194,304（官方 requestImagePixelBudget 默认） | 接管官方参数：保存时写入当前全部 pi-ai 路由；「恢复默认」同时**清除**各路由覆盖值回到官方默认 |
| 每条消息解析上限（张） | 20（官方 maxImagesPerMessage 默认） | 前 N 张获机器描述，其余仅归档（可回看）；下调省解析耗时/成本 |
| 多图解析并行数 | 4 | 一条消息贴多图时同时进行的解析调用数（1–8）；解析全部完成后主请求才发出，不与会话模型执行并行冲突 |

字段 ⓘ 帮助内含常用预设值（512²/1024²/2048²）与完整披露（入会归一化 2048² 封顶；不覆盖 DeepSeek 原生路由；模型页编辑路由后请「重新应用到全部路由」）。

## 安装 / 卸载

```sh
# 安装（桌面 profile）
cd ~/.dsh/profiles/desktop
# package.json: dependencies 加 "dsh-mm-resilience": "link:/Volumes/IPFSJK/Zcode/dsh-mm-resilience"
#              dsh.profile.bundles 加 "dsh-mm-resilience"
pnpm install   # 完全退出并重启 DSH（ClientModuleRegistry 负缓存，热改不生效）
```

卸载=删除上述两处条目 + `pnpm install` + 重启。DSH 客户端本体（/Applications）零改动。

## 桌面验收清单（重启 DSH 后）

1. ☐ 卡片=无边框官方扁平风格：区块标题「图片上限/图片解析」旁 ⓘ**悬停**出短提示（≤3 短句）；字段标签后**无 ⓘ**、说明为输入框下单行 hint
2. ☐ 全页**无孤立半宽分隔线**
3. ☐ 像素上限默认 4194304、解析上限默认 20、并行数默认 4（官方接管态）；未改动时「保存」置灰、改动后点亮（官方行为）
4. ☐ 修改任一字段→点「保存」：值落库；若保存未生效，提示行会显示诊断信息（status/writable/revision）——请连同 DevTools 控制台 `[mm-resilience]` 两行日志一并截图反馈
5. ☐ 成功保存过一次后，字段出现「已覆盖」徽章+「恢复默认」→点击→保存→值回官方默认（像素字段同时清除全部路由覆盖=官方参数完全回退）
6. ☐ 底部仅一行弱化「重新应用到全部路由」+状态文字（保存后的路由应用提示在此显示）
7. ☐ 插件页右上官方开关：关→官方自动接管（可能提示需重启）；开→设置不丢
8. ☐ 贴一张截图：缩略图保留+归档标签；网络面板确认第一个模型请求无图片 base64；解析上限改 1 连贴 2 图→第二张「未解析（超出每条消息解析上限…）」
